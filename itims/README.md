# ITIMS – IT Infrastructure Management System

A web application for an organisation's IT department to manage **computers, hardware, IP addresses, network devices, ISP links, firewalls, Wi-Fi access points, servers, CCTV cameras and IT complaints**, with a live dashboard and PDF/Excel reports.

> This project was generated by giving the prompt in [`PROMPT.md`](./PROMPT.md) to Claude (Anthropic's AI assistant).

## 2. How to Run

### Prerequisites
- Node.js 18 or newer
- PostgreSQL 14 or newer, running locally
- An empty database, e.g. `CREATE DATABASE itims;`

### Backend
```bash
cd backend
npm install
cp .env.example .env          # then edit DATABASE_URL with your PostgreSQL user/password
npx prisma migrate dev        # creates the 13 tables
npx prisma db seed            # loads demo data
npm run dev                   # API on http://localhost:5000
```

### Frontend (new terminal)
```bash
cd frontend
npm install
cp .env.example .env          # VITE_API_URL=http://localhost:5000/api
npm run dev                   # open http://localhost:5173
```

### Frontend-only presentation demo (no backend or database)
```bash
cd frontend
npm run demo                  # open the Vite URL shown in the terminal
```
This mode uses in-memory sample data and a demo administrator; changes are temporary and reset when the page reloads. It is only enabled by the `demo` script.
The demo mode is development-only; normal production builds keep the standard login and API behavior.

## 3. Architecture (3-Tier)

```
 ┌──────────────────────┐   HTTP + JSON    ┌──────────────────────┐   Prisma ORM   ┌──────────────┐
 │  PRESENTATION TIER   │ ───────────────▶ │   APPLICATION TIER   │ ─────────────▶ │  DATA TIER   │
 │  React (Vite)        │  Axios + JWT     │  Node.js + Express   │   SQL queries  │  PostgreSQL  │
 │  Tailwind, Recharts  │ ◀─────────────── │  Routes→Middleware→  │ ◀───────────── │  13 tables   │
 │  pages / components  │ {success,data,   │  Controllers         │                │              │
 └──────────────────────┘    message}      └──────────────────────┘                └──────────────┘
```

**Request flow example (Add Server):**
1. User fills the form in React → Axios sends `POST /api/servers` with the JWT token.
2. Express `protect` middleware verifies the token → `crudRouter` sends it to the server controller.
3. Controller runs the **duplicate-IP check**, then Prisma does `prisma.server.create()`.
4. PostgreSQL saves the row → response `{ success: true, data: {...}, message: "Created successfully" }`.
5. React shows a green toast and reloads the table.

### Reusable Generic CRUD Pattern
- **Backend:** `makeCrud('server', options)` in `crudFactory.js` returns `list / getOne / create / update / remove` for any Prisma model (search, filters, pagination, date conversion, optional IP check). `crudRouter(ctrl)` turns them into 5 REST routes. Most modules are **one line** in `moduleControllers.js`.
- **Frontend:** `<CrudPage config={...}/>` gives every module search, status filter, pagination (10 rows), Add/Edit modal, and delete confirmation. A page only describes its columns and form fields.

## 6. How Duplicate-IP Validation Works

All logic lives in **one reusable helper**: `backend/src/middleware/ipValidator.js`.

1. **Format check** – `isValidIPv4()` accepts only 4 numbers 0–255 (e.g. `10.10.20.15`). Invalid → **HTTP 400**.
2. **IP table** – creating/updating an `IpAddress` with an IP that already exists → **HTTP 409** `Duplicate IP: 10.10.10.10 already exists in IP Address Management.`
3. **Any device module** (Computer, Access Point, Server, CCTV, Network Device, Firewall) – before saving, `checkIpConflict()`:
   - searches every device table for the same IP (ignoring the record itself on update), and
   - checks the IP table: if the IP is ALLOCATED/RESERVED to a different device → **HTTP 409** with the device name.
4. **Auto-sync** – after a device is saved, `allocateIp()` marks that IP as ALLOCATED to the device in the IP table; on delete/IP change, `releaseIp()` frees it again.
5. **Database safety net** – `ipAddress` has a `UNIQUE` constraint, so even a bug cannot create two equal rows (Prisma error P2002 → 409).
6. **Frontend** – when the user leaves the IP field, the form calls `GET /api/ips/check`; any error is shown in **red directly under the IP field**. Save errors (409) are shown the same way.

The generic CRUD factory switches this on with one option: `ip: { field: 'ipAddress', nameField: 'name', deviceType: 'Server' }`.

## 7. How the Complaint Workflow Works

```
 OPEN ──assign──▶ ASSIGNED ──start──▶ IN_PROGRESS ──resolve (note required)──▶ RESOLVED ──close──▶ CLOSED
                                            ▲                                       │
                                            └──────────── re-open ──────────────────┘
```
- `POST /api/complaints` creates the ticket with an auto number (`TKT-0001`, `TKT-0002`, …) and status OPEN.
- `PATCH /api/complaints/:id/assign` sets the IT staff member (+ optional priority) → ASSIGNED.
- `PATCH /api/complaints/:id/status` moves to the next step. The backend keeps an **allowed-next-status map** and rejects skipping steps (e.g. OPEN → CLOSED gives HTTP 400).
- RESOLVED requires a `resolutionNote`; `resolvedAt` and `closedAt` timestamps are saved automatically.
- The detail screen shows a **stepper timeline** and only the buttons valid for the current status. Priority & status badges are colour-coded.

## 8. API Summary

All responses: `{ "success": true|false, "data": ..., "message": "..." }`. All routes except login need `Authorization: Bearer <token>`.

| Method | URL | Notes |
|---|---|---|
| POST | /api/auth/login | returns token + user |
| GET | /api/auth/me | current user |
| GET/POST/PUT/DELETE | /api/users | ADMIN only |
| GET | /api/dashboard/stats | all dashboard numbers |
| CRUD | /api/computers, /hardware, /ips, /network-devices, /switches, /isps, /firewalls, /access-points, /servers, /cctv, /complaints, /maintenance | list supports `?search=&page=&limit=&status=...`; `limit=0` returns all rows (used by reports); DELETE = ADMIN only |
| GET | /api/ips/summary, /api/ips/check?ip= | IP pool summary, live duplicate check |
| PATCH | /api/complaints/:id/assign, /api/complaints/:id/status | workflow |

Import `postman_collection.json` into Postman, run **Auth → Login (Admin)** first (token is saved automatically), then try any request. It includes ready-made "Duplicate IP → 409" tests.

## 9. Troubleshooting
- **`P1001: Can't reach database`** – PostgreSQL is not running or `DATABASE_URL` is wrong.
- **Port already in use** – change `PORT` in `backend/.env` and `VITE_API_URL` in `frontend/.env`.
- **Reset demo data** – run `npx prisma db seed` again (it clears and reloads everything).
