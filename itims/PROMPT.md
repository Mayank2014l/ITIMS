# Prompt used to build this project

This entire project (backend, frontend, database schema, seed data, Postman collection, README and VIVA notes) was generated by giving the following prompt to **Claude** (AI assistant by Anthropic).

---

You are a senior full-stack engineer. Build a complete, working, good-looking web application called "IT Infrastructure Management System (ITIMS)" for an organisation's IT department. It must be SIMPLE in code structure (so a student can explain it in a viva), but look like a modern professional admin dashboard.

## 1. TECH STACK (strict)
- Frontend: React.js (Vite) + Tailwind CSS + React Router + Axios + Recharts (charts) + lucide-react (icons)
- Backend: Node.js + Express.js REST APIs (3-tier architecture: React -> Express -> Prisma -> PostgreSQL)
- Database: PostgreSQL with Prisma ORM
- Auth: JWT + bcrypt, role-based access control (ADMIN, IT_STAFF)
- Reports: PDF (jspdf + jspdf-autotable) and Excel (xlsx) export, done on the frontend
- Testing: provide a Postman collection JSON file for all APIs

## 2. PROJECT STRUCTURE
/itims
  /backend  (src/routes, src/controllers, src/middleware, src/prisma, server.js, prisma/schema.prisma, prisma/seed.js, .env.example)
  /frontend (src/pages, src/components, src/api, src/context, src/layouts)
  README.md (setup steps + simple explanation of architecture, each module, and ER diagram in text)
  postman_collection.json

Keep code clean, commented in simple English, and avoid over-engineering. Use ONE reusable generic CRUD pattern:
- Backend: a helper that creates list/create/update/delete controllers for a Prisma model, reused by simple modules.
- Frontend: a reusable <DataTable>, <FormModal>, <StatusBadge>, <StatCard>, <PageHeader> used by every module page with search, filter, pagination, add/edit/delete.

## 3. DATABASE (Prisma schema, exactly 13 tables)
1. User: id, name, email (unique), password, role (ADMIN | IT_STAFF), createdAt
2. Computer: id, assetTag (unique), name, assignedTo, department, location, processor, ram, storage, os, macAddress, ipId (optional relation to IpAddress), status (ACTIVE | INACTIVE | UNDER_REPAIR), purchaseDate
3. HardwareInventory: id, itemType (Printer/Scanner/UPS/Monitor/Other), brand, model, serialNo, location, status, purchaseDate, warrantyEnd
4. IpAddress: id, ipAddress (UNIQUE), subnet, vlan, deviceType, deviceName, assignedDate, status (ALLOCATED | FREE | RESERVED), remarks
5. NetworkDevice: id, name, type (Router/Switch/Modem/Other), brand, model, location, ipAddress, status
6. Switch: id, networkDeviceId (relation), totalPorts, portNumber, connectedDevice, vlan, portStatus (UP | DOWN)
7. Isp: id, providerName, linkType (PRIMARY | BACKUP), bandwidth, circuitId, staticIp, contactPerson, contactNumber, status (ACTIVE | DOWN)
8. Firewall: id, name, brand, model, ipAddress, firmwareVersion, policiesSummary, licenseExpiry, status
9. AccessPoint: id, name, location, ipAddress, macAddress, ssid, status (ONLINE | OFFLINE)
10. Server: id, name, role, brand, os, ipAddress, rackNumber, patchPanel, location, status
11. CctvCamera: id, cameraName, cameraType (ANALOG | IP), location, recorderType (DVR | NVR), recorderName, ipAddress, status (WORKING | NOT_WORKING)
12. Complaint: id, ticketNo (auto, e.g. TKT-0001), title, description, category (Hardware/Network/Software/CCTV/ISP/Other), priority (LOW | MEDIUM | HIGH | CRITICAL), status (OPEN | ASSIGNED | IN_PROGRESS | RESOLVED | CLOSED), raisedBy, assignedToId (User), resolutionNote, createdAt, resolvedAt, closedAt
13. MaintenanceRecord: id, deviceType, deviceName, recordType (MAINTENANCE | ISP_DOWNTIME | SECURITY_INCIDENT), description, date, performedBy, remarks

(ISP downtime history and firewall security incidents are stored in MaintenanceRecord using recordType.)

## 4. MODULES (12) - each gets a sidebar menu item and a page
1. Login & Authentication: login page, JWT, protected routes. ADMIN = full access incl. delete and user management; IT_STAFF = add/edit/view, no delete.
2. Dashboard: stat cards (Total Computers, Total Devices, Active ISP Links, Pending Complaints, CCTV Working/Not Working, Free IPs), Recharts: device status donut, complaints by category bar chart, complaints by status chart, ISP link status, recent complaints table.
3. Computer & Hardware: two tabs (Computers, Hardware Inventory).
4. IP Address Management: DUPLICATE IP VALIDATION is mandatory. Backend must reject duplicate IPs with a clear error message (HTTP 409) and also validate IPv4 format. Frontend shows an inline red error. Show a "Free / Allocated" summary and filter by subnet/VLAN.
5. Network Management: network devices + switch port details, simple topology view (a clean card/diagram layout showing Internet -> Firewall -> Core Switch -> Access Switches -> Devices using React + SVG/CSS, no heavy libraries).
6. ISP Management: providers, bandwidth, PRIMARY/BACKUP, status toggle, downtime records.
7. Firewall & Security: firewall details, policy summary, security incident records.
8. Wi-Fi & AP Management: AP list with location, IP, MAC, SSID, ONLINE/OFFLINE badge.
9. Server Room Management: servers, rack and patch panel info, maintenance records.
10. CCTV Management: camera list, analog/IP, DVR/NVR, working status, summary cards.
11. IT Complaints: create -> assign to IT staff -> prioritise -> in progress -> resolve (with note) -> close. Show a status timeline/stepper on the complaint detail view, and colour-coded priority/status badges.
12. Reports & Analytics: report cards for Inventory, IP, ISP, CCTV, Complaints; each with filters and "Download PDF" / "Download Excel" buttons.

## 5. DUPLICATE IP RULE
Duplicate check must exist in: (a) IpAddress create/update, (b) whenever any module (Computer, AP, Server, CCTV, Network device, Firewall) saves an ipAddress, check it against IpAddress table and reject if already allocated to another device. Implement this as one reusable middleware/helper.

## 6. UI / UX REQUIREMENTS
- Modern, clean admin dashboard: left sidebar (collapsible, icons), top navbar with user name/role and logout, light theme with blue/indigo primary colour, rounded cards, soft shadows, smooth hover effects.
- Fully responsive. Loading spinners, empty states, toast notifications for success/error, confirm dialog before delete.
- Colour badges: green = Active/Working/Online/Resolved, red = Down/Offline/Not Working/Critical, yellow = Pending/Medium, blue = Open/In Progress.
- Search box and status filter on every table; pagination (10 rows per page).

## 7. SEED DATA
Create prisma/seed.js with realistic demo data: 
- Users: admin@itims.com / Admin@123 (ADMIN), staff@itims.com / Staff@123 (IT_STAFF)
- ~15 computers, ~10 hardware items, ~30 IPs, 5 network devices with switch ports, 2 ISPs (1 primary, 1 backup), 2 firewalls, 8 access points, 5 servers, 12 CCTV cameras, 15 complaints in mixed statuses, ~10 maintenance records.
So the dashboard looks full and impressive on first run.

## 8. API DESIGN
RESTful, prefixed /api: /auth/login, /auth/me, /users, /computers, /hardware, /ips, /network-devices, /switches, /isps, /firewalls, /access-points, /servers, /cctv, /complaints (+ PATCH /:id/assign, /:id/status), /maintenance, /dashboard/stats. Consistent JSON response format { success, data, message }. Central error handler. Input validation.
